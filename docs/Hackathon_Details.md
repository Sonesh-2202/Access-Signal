## 3. What to Build

Build a **working software application using Kiro** (IDE, CLI, Web and/or Kiro Crew) and enter **one** category.

| Category | Brief |
|---|---|
| **Resurrection** | Bring a dead/obsolete technology back to life with today's innovations |
| **Frankenstein** | Stitch seemingly incompatible technologies into one unexpectedly powerful app |
| **Skeleton Crew** | A lean, flexible skeleton template, shown with **two distinct applications** built from it |
| **Costume Contest** | Any app, with a polished, unforgettable, spooky UI that enhances function |

### Project rules
- **New projects only**, built during the Submission Period (Oct 30 – Dec 4, 2026). Anything started before Oct 30, including Kiroween 2025 projects, is ineligible.
- Standard frameworks, libraries and starter templates are fine. Any other pre-existing code must be disclosed.
- Must install and run consistently on its intended platform and work as shown in the video and description.
- Third-party SDKs/APIs/data require proper authorization and licence compliance.
- Insufficient use of Kiro can lead to disqualification.
- Multiple submissions are allowed, but each must be unique and substantially different.
- Teams can't use work developed with financial or preferential support from AWS or Devpost.

## 5. Kiro Usage Write-Up — Prompts to Answer

Judges must see **how effectively and deeply** Kiro was used.

| Topic | Questions to address |
|---|---|
| **Kiro IDE / CLI / Web / Crew** | Which did you use? How did they differ if you tried several? |
| **Custom agents** | Did you create or use any? In which Kiro app? How did they affect the build? |
| **Agent hooks** | What workflows did you automate? How did they improve development? |
| **Spec-driven development** | How did you structure specs? How did it help, and how does it compare to vibe coding? |
| **Steering docs** | How did you use steering to improve responses? Which strategy mattered most? |
| **MCP** | What capabilities or workflow improvements did MCP enable that would've been hard otherwise? |
| **Property-based testing (PBT)** | Did PBT catch issues unit tests missed? For what kinds of requirements? |
| **Kiro powers** | Which powers did you use? Any third-party tooling or integrations you wouldn't have had otherwise? |

## 6. Judging

### Stage 1 — Pass/Fail
Does the project reasonably fit the theme and reasonably apply the required tools?

### Stage 2 — Scored (5 criteria, equally weighted: 20% / 10 pts each)

| Criterion | What judges look at |
|---|---|
| **Potential Impact** | Real problem, real audience? Useful, intuitive, accessible? Would someone actually use it? |
| **Technological Implementation** | How thoroughly and skillfully is Kiro used? Thoughtful AI-development strategy? Variety of Kiro tools? Experimentation? |
| **Design** | Complete, coherent, polished product experience, not just a technical proof of concept? |
| **Innovation / Idea** | Creative and novel? Unusual technologies or public datasets combined in a unique way? |
| **Presentation** | Video shows end-to-end working project? Clear pitch (problem, audience, why it matters)? Easy to follow, creative, memorable? |

**Tie-break:** tied entries are re-scored from scratch with a 20-point max per criterion, adding +10 per additional round until a winner emerges.

> Judging may use expert panels, peer review, automated AI-driven analysis, or a combination.
